# dsh-deepseek-pricing

DSH（DeepSeek Harness）插件：在输入框工具栏显示 DeepSeek API 当前是**高峰**还是**空闲**计费时段、距离下次切换还有多久，并在设置页同步官方各模型单价。

- 输入框工具栏徽章：`高峰 · 全价` / `空闲 · 半价` + 倒计时，点击展开今日时段与价格小卡片。
- 设置 →「DeepSeek 价格」：完整价格表（¥ / $ 可切换）、时段规则、节假日状态、数据来源、手动刷新。
- 每轮花费估算（可选，默认关闭）：在已完成轮次的页脚上方显示 `~¥1.22`，悬停查看完整精度与分项。
- 功能开关：设置页里集中管理花费估算、查询工具、节假日同步、刷新间隔；最常用的两个也出现在**本插件详情页**上。
- 可选 AI 工具 `deepseek_pricing`：让模型自己判断"现在贵不贵、要不要等到空闲时段"。

## 安装

```sh
dsh plugin --profile <profile名> add dsh-deepseek-pricing
```

或在 DSH 的 **插件（Plugins）→ 添加插件** 里输入包名 `dsh-deepseek-pricing`，装好后重启一次 DSH。
从源码目录安装则把包名换成该目录的绝对路径。

## 计费时段规则

来源：[DeepSeek 官方定价页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing)（脚注 2）

- 高峰：**北京时间（UTC+8）周一至周五 09:00–12:00、14:00–18:00**，不含中国法定节假日。
- 空闲：其余全部时间，包括周末与中国法定节假日全天。
- 空闲价 = 高峰价的一半。

周末补班（调休上班日）不影响判定：规则本身已把周末定义为全天空闲。

## 价格与节假日数据

| 数据 | 来源 | 回退 |
|---|---|---|
| 模型价格（¥） | `https://api-docs.deepseek.com/zh-cn/quick_start/pricing.md` | 内置快照 → 上次成功值 |
| 模型价格（$） | `https://api-docs.deepseek.com/quick_start/pricing.md` | 内置快照 → 上次成功值 |
| 法定节假日 | `https://timor.tech/api/holiday/year/{year}` | `holiday-cn`（GitHub）→ 内置 2026 快照 |

- 价格默认每 360 分钟自动刷新一次，也可在设置页手动刷新；抓取失败时界面会明确标注"离线快照"与数据时间。
- 节假日数据按当前年 + 次年的顺序获取；次年数据尚未发布时会提示"尚未发布，假期期间可能误判为高峰"。
- **一次刷新失败不会丢数据**：每次成功抓到的日历会按年份记住，之后失败只标成「沿用上次」（含上次成功时间与失败原因），高峰判定继续用旧日历，不会退化成"没有节假日"。只有从未成功抓过、也没有内置快照的年份才会显示「获取失败 / 按无节假日计算」。
- **节假日缓存写在包目录内**（`<包目录>/.cache/holidays.json`，约 3 KB）。卸载会删除整个包目录，缓存随之消失；升级或重装会重建目录，缓存丢失（它只是缓存，下一次抓取就会补回）。缓存里只保留当年与次年。
- **抓取时机**（节假日）：① 冷启动后第一次状态请求，缓存缺失或已超过 7 天时同步抓一次；② 缓存 7 天内，重启**完全不联网**；③ 连续运行满 7 天，下一次状态请求触发一次后台刷新；④ 失败时前 3 次每 60 秒重试、之后每 15 分钟；⑤ 手动点「刷新」立即抓取；⑥ 跨年时抓「当年 + 次年」，缓存里的旧年份自动剪掉。稳定状态下是**每周一次**。
- 状态含义：`已同步`（最近一次抓取成功）、`沿用上次`（本次失败，用上次成功的日历）、`本地缓存`（关闭了自动同步，用磁盘里上次成功的数据）、`内置快照`（从未抓成功，用内置数据）、`尚未发布`（数据源明确返回空）、`检查中`（首次抓取进行中）。
- **第一次状态请求不再等待抓取**：冷启动先用内置快照回答（当年数据可用，次年标记「检查中」），抓取在后台完成后由页面在 5s/20s/75s 各补读一次。抓取本身给 20 秒超时（实测 timor 偶尔要 11 秒），所以"超时导致状态乱跳"不会再发生。
- 解析采用"关键词识别 + 末尾金额"的双路匹配，并对"高峰价 = 2 × 空闲价"做校验；官方页面结构变化时宁可保留旧值，也不显示半解析结果。

## 每轮花费估算

- 开关在设置页「功能开关」里（本插件详情页也有同一个）；模型映射与数字格式合并在「花费估算」一张卡片里，紧跟在功能开关下面。**默认关闭**；设置只保存在本浏览器。
- 费用 = 未缓存输入 × 未命中价 + 缓存读取 × 命中价 + 输出 × 输出价，按**该轮结束时刻**的高峰/空闲价计算；跨 18:00 的轮次整轮按结束时段计价。
- 只对已完成、且官方用量完整的轮次显示。模型从用量里的 provider/model 识别（含 flash / pro）；识别不到时可在映射表里按 `provider/model` 指定，或设为「不计价」。
- 悬停提示显示完整精确小数、分项、时段与价格快照时间。
- 数字写法在「花费估算」卡片的下半部分「数字格式」里调（见下节）；默认 `~¥1 234.568`。
- 数据缺失（缺路由、缺缓存读取、模型无法识别、混合模型、价格不可用）时只显示 `~`，悬停说明原因。
- 位置限制：插件无法插进 ui-chat 的「用量 · 时间」那一行，只能渲染在它**上方、右对齐**（`conversation.chat.turnTail`）。

## 数字格式

「花费估算」卡片里的「数字格式」区块只改显示，不改价格：

| 设置 | 可选 | 默认 |
| --- | --- | --- |
| 分隔符 | 空格 / 英文逗号 `,` / 竖线 `\|` / 竖虚线 `┊` / 不分隔 | 空格 |
| 分组 | 每 3 位（`1 234 567`）/ 每 4 位（`1┊2345┊6789`） | 每 3 位 |
| 小数位 | 1–8 | 3 |
| 小额显示 | `~¥0.000…` / `<¥0.001` | `~¥0.000…` |

- **固定位数**：选 3 位就显示 3 位（`1.220` 不会缩成 `1.22`），四舍五入，进位会进到整数部分（`0.9999` → `1.000`）。
- **小数部分也分组**：选 8 位小数时是 `12.345 678 90`；默认 3 位时小数不够一组，看不到分隔符。
- **小额兜底**：四舍五入后为 0 但确有花费时，按上面选的模式显示 `~¥0.000…` 或 `<¥0.001`（`<` 模式不带 `~`）。
- **悬停提示**跟随分隔符与分组，但始终是完整精度，不受小数位影响；价格表与弹出卡片不受影响。
- 设置存在 `localStorage` 的 `dsh-deepseek-pricing.cost` 里（与开关、映射同一个键），老版本数据缺字段会自动落默认值。

## 功能开关

开关分三层，**各归其位**，不会互相顶替：

| 层 | 位置 | 控制什么 |
| --- | --- | --- |
| 插件总开关 | 设置 → 插件 → 本插件 | bundle 是否启用 |
| 组件开关 | 设置 → 插件 → 本插件 → 包含的组件 | `deepseek-pricing` 这一行是否运行 |
| 功能开关 | 设置 → DeepSeek 价格（完整）/ 本插件详情页（常用） | 插件内部行为 |

功能开关本身：

| 开关 | 存哪 | 生效 |
| --- | --- | --- |
| 每轮花费估算 | 浏览器 localStorage | 立即 |
| AI 查询工具 `deepseek_pricing` | profile 的 `cordis.patch.yml` | 本插件重载（约 1 秒） |
| 同步法定节假日 | 同上 | 同上 |
| 价格自动刷新间隔 | 同上 | 同上 |

- Host 侧开关通过 `POST /api/deepseek-pricing/config` 写入，内部走 DSH 的 `configEditor`，所以配置**只有一个真源**（profile patch 里那一行），重启后仍然有效，卸载时随行消失。
- 写入完成前先回 202，再由 Loader 重新应用本行；页面在 1.2s / 3s 后重新读取 `/state`，因此看到的值总是已持久化的值，而不是乐观更新。
- 插件详情页的卡片只在你打开本插件那一页时渲染（按 `subject` 过滤），别人的插件页不受影响。
- 若当前 DSH 版本没有 `configEditor` 服务，接口返回 501，界面提示手动编辑 `cordis.patch.yml`，不会静默失败。

## 配置

插件不导出 Config schema，配置直接写在 `cordis.patch.yml` 的行上（从源码目录、以 `link:` 方式安装时，裸 `@deepseek-ai/*` 依赖还会因为真实路径解析不到，所以保持无 schema 最稳）：

```yaml
- id: deepseek-pricing
  name: dsh-deepseek-pricing
  config:
    tool: true            # 是否注册 deepseek_pricing 工具（默认 false）
    currency: CNY         # 默认币种：CNY / USD（默认 CNY）
    refreshMinutes: 360   # 价格自动刷新间隔，0 = 仅手动（默认 360）
    holidayRefresh: true  # 是否同步法定节假日（默认 true）
```

- `tool` 为 `true` 时，模型会多一个无参数的 `deepseek_pricing` 工具；关闭时模型侧零开销。
- `tool`、`refreshMinutes`、`holidayRefresh` 可以在界面里改（见上一节），改完会写回这条行；`currency` 只作为界面显示偏好，不写回配置。
- 界面里的 ¥ / $ 切换只影响显示，保存在浏览器 localStorage。

## 已知限制

- 启动顺序：Web 服务是在插件行开始激活之后才发布 `webServer` 服务的。Host 端用 `export const inject = ['webServer']` + `ctx.inject(['webServer'], …)` 等待并注册路由（与 `dsh-model-health`、`dsh-our-free-model` 同一模式），所以冷启动后路由会自动出现，不需要手动禁用/启用插件。
- 页面仍可能在路由注册前就发出第一次请求；客户端对失败做退避重试（1s/2s/4s…最多 30s），切回标签页也会重试，弹出卡片里还有「重试」按钮。
- DSH 的模型目录没有价格字段，本插件只能维护自己的价格表，不会改写模型配置。
- 每轮花费估算按轮结束时刻取价，跨时段轮次不拆分；只是估算，不替代账单。缓存写入没有单独价格，未计入。
- 官方页面改版导致解析失败时，价格停留在上次成功值或内置快照，界面会提示。
- 节假日以官方发布的法定节假日为准；次年安排通常要到年底才公布。
- 窗口弹出卡片使用固定定位；若宿主后续给输入框容器加上 `transform`/`contain` 导致裁剪，可改为 `conversation.composer.dock` 内的常驻条。

## 卸载

正常卸载：**插件（Plugins）→ dsh-deepseek-pricing → 移除**（内部执行 `plugin_manager remove_bundle`）。它会移除 profile 的依赖、bundle 选择、`node_modules` 副本和锁文件条目，同时卸载 Host 路由与客户端槽位。

插件自身不写 profile 数据、不写会话事件、没有后台任务。唯一的磁盘文件是**包目录内的节假日缓存**（`node_modules/dsh-deepseek-pricing/.cache/holidays.json`），它随包目录一起被卸载删除，**不需要手动清理**。

同一份清单也显示在**插件详情页**（设置 → 插件 → 本插件）的「卸载说明」里，并标注每一项都是**可选**的：不清理没有任何副作用，介意残留再按操作处理。卸载后仍可能留下这些**外部**痕迹：

- **浏览器本地设置**：`localStorage` 里的 `dsh-deepseek-pricing.currency` 与 `dsh-deepseek-pricing.cost`。到设置页「花费估算」点 **清除本地设置** 即可（不用卸载也能清）。
- **行级配置残留**：在界面里动过「查询工具 / 节假日 / 刷新间隔」之后，`cordis.patch.yml` 里会多出一条 `- id: deepseek-pricing` 覆盖（由 `configEditor` 写入，不是本插件自己写文件）。把值改回默认值时 DSH 会自己清掉这条；没清掉也不影响，卸载后它不再生效，可直接删除。
- **pnpm 发布龄豁免**：如果安装的版本发布还不到 pnpm 的 `minimumReleaseAge`，pnpm 会在 profile 的 `pnpm-workspace.yaml` 里写一条 `minimumReleaseAgeExclude: dsh-deepseek-pricing@x.y.z`；这是 pnpm 的行为，卸载不会自动删，可手动删除。

以上三条都不影响 DSH 或其它插件；删掉后 profile 就回到安装前的状态。
